# Pokémon Seal Archive

한 저장소에서 만드는 세 가지 프로그램입니다. 띠부씰을 기록하고 키우는 **Holo**, 내가 고른 포켓몬으로 겨루는 **Proelium**, 둘이 함께 쓰는 배틀 엔진 **Rembrandt**.

| 프로그램 | 버전 | 한 줄 소개 | 주소 |
|---|---|---|---|
| **Holo** | 4.0 | 포켓몬 띠부씰 아카이브. 도감·바인더·사육장·3:3 배틀 탭 (**Rembrandt 1.1 탑재**) | `/` |
| **Proelium** | 1.0 | 포켓몬 3마리와 기술 4개를 직접 고르는 배틀 아레나 (**Rembrandt 1.1 탑재**) | `/proelium/` |
| **Rembrandt** | 1.1 | 화면 없는 배틀 엔진: 규칙·데미지·변화기·AI·상대 파티 생성 | (라이브러리) |

별도 서버나 외부 API 키 없이 정적 웹앱으로 동작하며, 모든 데이터는 브라우저 저장소(localStorage)에 보관됩니다.

# Holo 4.0

포켓몬 띠부씰의 세대·속성·등급 정보를 기록하고, 실시간 통계와 도감 완성 예측을 보여주는 웹앱입니다.
수집한 씰은 **바인더**처럼 펼쳐 볼 수 있고, **띠부파를레 사육장**에서 포켓몬과 교감하거나 **3:3 배틀**로 겨뤄 볼 수 있습니다. 소스는 `apps/holo/index.html` 한 파일입니다.

## 주요 기능 한눈에 보기

| 탭 | 내용 |
|---|---|
| **도감 아카이브** | 씰 등록·수정·삭제, 핵심 지표, 세대별 완성률, 속성·등급 차트, 완성 예측 시뮬레이터, 목록/바인더 보기 |
| **띠부파를레** | 최대 6마리 사육장, 낮·노을·밤 테라스, 쓰다듬기·간식·말 걸기로 친밀도 올리기 |
| **배틀** | 보유 씰 3마리로 AI와 3:3 턴제 배틀(변화기 150개 포함), 난이도 3단계, 전적 저장 |
| **데이터 관리** | JSON 백업·복원, 타입 일괄 동기화, 샘플 로드, 전체 초기화 |

## 실행 방법

- **바로 쓰기:** 배포된 주소(`/`)를 엽니다.
- **개발 서버:** Node.js 설치 후 `npm install` → `npm run dev:holo` → http://localhost:3000
- **배포용 빌드:** `npm run build` → `dist/`(Holo)와 `dist/proelium/`(Proelium)가 만들어집니다. 정적 호스팅에 올리면 됩니다. 파일을 직접 더블클릭해서 여는 방식은 지원하지 않습니다.
- **인터넷 연결:** 스타일·차트·아이콘 라이브러리(CDN)와 포켓몬 공식 일러스트 이미지를 외부에서 불러오므로 접속 환경이 필요합니다. 속성(타입) 정보는 내장 표를 우선 사용하고, 없을 때만 PokeAPI로 보완합니다.

## 도감 아카이브

### 1. 핵심 지표
상단 카드에서 다음 수치를 실시간으로 보여줍니다.

- 총 보유 수량 · 고유 종수
- 최다 보유 속성 TOP 1과 점유율
- 30주년 기념 씰 수와 전체 대비 비율
- 미개봉 수와 비율
- 도감 완성률(중복 제외, 1,025종 기준)
- 최고 수집 세대

### 2. 세대별 도감 완성률
1~9세대(관동·성도·호연·신오·하나·칼로스·알로라·가라르/히스이·팔데아)별로 공식 도감 수록 수 대비 몇 %를 모았는지 중복 제외 기준으로 집계합니다. 전국도감 전체 완성률도 함께 표시합니다.

### 3. 차트
- **세대별 현황:** 수집률(%) / 보유 수량 전환
- **18개 속성 분포:** 레이더 / 막대 차트 전환
- **등급 및 에디션 비율:** 미개봉·일반·하자, 그리고 씰 종류별 비율

### 4. 확률론적 도감 완성 예측 (CCP)
쿠폰 수집가 문제(Coupon Collector's Problem)를 이용한 예측 도구입니다. 모든 띠부씰의 출현 확률이 같다고 가정하고, 남은 도감을 모두 채우기 위한 기대 구매 횟수와 비용을 계산합니다.

- 기댓값: `E[X] = N × Σ(1/m)` (m = 1 ~ 남은 종수, N = 분석 범위의 총 종수)
- 분석 범위: 전체 1,025종 또는 세대별 선택
- 빵 1개 단가를 직접 입력할 수 있음 (기본 2,000원)
- 현재 수집 현황, 달성률, 남은 목표·비중, 추가 구매 기대치(봉지), 예상 추가 지출을 표시

### 5. 띠부씰 등록·수정
`새 띠부씰 등록` 버튼으로 엽니다.

- **도감 번호 입력 시 세대 자동 판별**, 포켓몬 이름 자동완성(**초성 검색** 지원: 예 `ㅍㅋㅊ`)
- **씰 종류:** 일반 / 레트로 / 30주년 / 30주년 오리지널 컬러, 30주년 기념 씰 여부 표시
- **상태 등급:** 미개봉 / 일반 / 하자
- **특수 폼 & 이로치**
  - 메가진화 (87종 · X/Y 구분 포함)
  - 거다이맥스 (32종)
  - 리전폼 (알로라 18 · 가라르 19 · 히스이 16 · 팔데아 2, 총 55개 폼)
  - 폼체인지 (기라티나(오리진폼), 쉐이미(스카이폼), 냐오닉스(암컷의 모습) 등 86종 411개 폼)
  - 이로치(Shiny) 표시
  - 선택한 폼에 맞는 이름과 공식 일러스트가 자동 반영됨
- **직전 등록 설정 기억:** 연속 등록할 때 씰 종류·등급이 유지되어 빠르게 입력할 수 있음
- 속성(타입)은 도감 번호로 자동 매핑 (듀얼 타입 지원)

### 6. 컬렉션 보기

**목록 보기**
- 카드 / 테이블 형태 전환
- 검색: 이름 또는 도감 번호
- 필터: 세대, 속성(18종), 상태 등급, 종류/에디션, 30주년 씰만
- 정렬: 도감 번호 오름/내림차순, 최근 등록순, 오래된 등록순, 이름순(가나다)
- 페이지 이동, 다중 선택 후 일괄 삭제
- 이미지를 눌러 확대(라이트박스)하고 상세 정보 확인

**바인더 보기**
- 전국도감 **18포켓 양면 바인더**(9+9 포켓)를 펼친 것처럼 표시, 총 57페이지
- 보유한 칸은 씰이 채워지고 미보유 칸은 빈 포켓으로 표시
- 이전/다음 페이지 버튼, **키보드 좌우 방향키**로 넘기기
- 페이지 번호 직접 입력, 이름·번호 빠른 검색 후 해당 칸으로 이동
- 세대별 빠른 이동 버튼
- 칸을 누르면 해당 도감 번호의 보유 목록을 보고, 한 장 더 추가하거나 삭제할 수 있음
- 마지막으로 본 보기 방식과 바인더 페이지를 기억함

## 띠부파를레 사육장

상단 **띠부파를레** 탭에서 수집한 포켓몬을 최대 **6마리**까지 사육장(글래스 테라스)에 데려올 수 있습니다. 탭 옆 배지에 현재 인원(예: `2/6`)이 표시됩니다.

- **엔트리 관리:** 도감에서 사육장 멤버를 추가·교체. `추천 6마리 등록`으로 한 번에 채울 수도 있음
- **시간대 배경:** 낮(06:00~17:00) · 노을(17:00~19:30) · 오로라 밤(19:30~06:00). `실시간`을 고르면 현재 시각에 따라 자동 전환되고, 직접 고정할 수도 있음. 햇살 입자·별·반딧불 같은 연출이 곁들여짐
- **테라스 생활:** 포켓몬이 돌아다니고 방향을 바꾸며, 말풍선으로 속마음을 말함
- **1:1 글래스 교감실:** 테라스의 포켓몬을 누르면 열림. 이전/다음 버튼으로 다른 멤버로 이동
  - **쓰다듬기:** 마우스 또는 손가락으로 약 3초간 문지르면 친밀도 상승 (완료 후 1초 대기)
  - **포켓몬빵 간식:** 돌아온 로켓단 초코롤 / 돌아온 고오스 초코케익 / 파이리의 화르륵 핫소스빵(이스터에그). 먹이면 포만감 +1, 친밀도 +8이며 포만감이 5/5이면 더 먹지 않음
  - **한마디 건네기:** 최대 30자 메시지를 보내면 포켓몬의 성격 유형(귀여운 타입, 의리 있는 타입, 전설·드래곤 타입 등)에 맞춰 대답함
- **친밀도 5단계:** 0~19 / 20~44 / 45~69 / 70~89 / 90 이상, 하트로 표시
- **파트너 인사 배너:** 사육장 멤버 중 한 마리가 시간대에 맞는 인사와 응원 메시지를 건넴. 닫으면 이번 접속 동안 숨겨짐
- 사육장 상태는 도감과 동기화되어, 삭제된 씰은 사육장에서도 정리됨

## 배틀

상단 **배틀** 탭에서 내 띠부씰 3마리로 AI와 3:3 턴제 배틀을 할 수 있습니다. 배틀 엔진은 **Rembrandt 1.1**입니다.

- **규칙**: 전원 Lv.100(개체값 31 · 노력치 0 · 성격 보정 없음), 같은 종은 한 마리만, 종족값 합계 제한 없음. 특성·도구는 없습니다.
- **기술**: 포켓몬이 배울 수 있는 기술 중에서 **배틀마다 무작위로 4개**가 정해집니다(공격기 2~3 + 변화기 1~2, 같은 역할의 변화기는 겹치지 않음). 변화기를 못 배우는 포켓몬은 공격기만 가집니다. 정해진 기술은 상대 공개(VS) 화면에서 먼저 볼 수 있습니다.
- **변화기**: 상태이상·능력 변화·회복에 더해 날씨·필드·함정·벽·대타·방어 같은 지속 효과까지 150개를 지원합니다. 화면에는 날씨/필드 막대, 함정·벽, 씨뿌리기·도발 같은 상태가 표시되고, 도발 등으로 잠긴 기술은 버튼이 잠기며 이유가 나옵니다.
- **흐름**: 파티 편성(자동 편성 지원) → 난이도 선택(쉬움/보통/어려움) → 상대 파티 공개 → 배틀 → 결과(전적은 브라우저에 저장)
- **난이도**: 상대 파티의 종족값 합계가 내 파티 기준 −120 / 0 / +90으로 달라지고, AI의 실수율도 달라집니다.
- **조작**: 기술 버튼(또는 1~4 키) · 교체 · 항복 · 재생 속도(1~3x) · 연출 건너뛰기 · 전투 기록 · 상성 힌트 on/off

## 데이터 관리

상단 **데이터 관리** 메뉴에서 다음 작업을 할 수 있습니다.

| 메뉴 | 설명 |
|---|---|
| JSON 백업 내보내기 | 전체 컬렉션을 `pokemon_seals_backup.json`으로 저장 |
| JSON 파일 가져오기 | 백업 파일 복원. 파일 선택 또는 드래그 앤 드롭, **병합**(기존 데이터에 추가) / **덮어쓰기**(기존 데이터 교체) 중 선택 |
| 기존 데이터 타입 일괄 동기화 | 속성 정보가 누락된 포켓몬을 자동으로 채움 |
| 기본 샘플 데이터 로드 | 둘러보기용 샘플 씰 불러오기 |
| 전체 컬렉션 초기화 | 모든 씰 삭제 (확인 창이 뜸) |

- 가져오기 시 잘못된 항목은 걸러내고, 값을 검증·정규화하며, id 중복이 없도록 정리합니다.
- 이전 버전에서 저장된 데이터는 특수 폼 이름·이미지·타입 정보를 자동으로 보정합니다.
- 삭제나 초기화처럼 되돌릴 수 없는 작업은 확인 창을 거칩니다.
- 데이터는 **현재 브라우저에만** 저장됩니다. 브라우저 변경이나 사이트 데이터 삭제 전에 백업을 내려받아 두세요.

저장 키(localStorage): `pokemon_seal_db`(컬렉션), `pokemon_seal_habitat_v2`(사육장), `pokemon_seal_last_settings`(직전 등록 설정), `preferred_view_mode` · `preferred_binder_page`(보기 설정)이며, 배틀 전적도 브라우저에 저장됩니다.

## 기술 정보

- 구성: 순수 HTML/CSS/JavaScript 단일 페이지 앱 (빌드 도구는 Vite, 선택 사항)
- UI: Tailwind CSS(CDN) · Chart.js(차트) · Lucide(아이콘) · Pretendard(글꼴)
- 이미지: PokeAPI 공식 일러스트·스프라이트
- 배틀 모듈(`packages/`)은 일반 `<script>`로 불러오며, 빌드 시 `dist/packages/`로 복사됩니다.

# Proelium 1.0

내가 고른 **포켓몬 3마리**와 각자의 **기술 4개**로 AI와 겨루는 배틀 아레나입니다. 아카이브(Holo)가 정리된 도구라면 Proelium은 오락에 가깝게, 크고 화려하게 만들었습니다. 엔진은 **Rembrandt 1.1**입니다. 배포 주소는 `/proelium/`입니다.

## 화면 흐름

홈 → 팀 편성 → 매칭(VS) → 배틀 → 결과

| 화면 | 내용 |
|---|---|
| **홈** | 금색 고리가 도는 첫 화면. 내 팀 카드(포켓몬 타입 색으로 물든 카드), 배틀 시작·팀 편성·랜덤 팀, 전적(승·패·승률·연승) |
| **팀 편성** | 슬롯 3개. 포켓몬 선택창과 기술 선택 시트가 열립니다. 랜덤 팀, 슬롯 비우기, 같은 종 중복 방지 |
| **매칭(VS)** | 내 팀과 상대 팀(포켓몬·기술 공개), 종족값 합계 비교, 난이도 선택, 다른 상대 뽑기, 팀 수정 |
| **배틀** | 3:3 턴제. 기술 카드(타입 색, 위력·명중·PP, 상성 힌트), 교체, 항복, 재생 속도, 연출 건너뛰기, 효과음 on/off, 1~4 키 |
| **결과** | VICTORY / DEFEAT / DRAW, MVP(가장 많이 피해를 준 포켓몬), 턴 수·쓰러뜨린 수·연승, 한 번 더·새 상대·팀 수정·홈 |

## 팀 편성

- **포켓몬 1,351마리**(기본 1,025종 + 메가·리전·거다이맥스·폼 등)를 모두 고를 수 있습니다. 검색은 이름·**초성**(예: `ㅍㅋㅊ`)·도감번호, 필터는 타입 18종과 전체/기본/폼·메가/전설, 정렬은 도감순·종족값순·이름순입니다. 한 번에 60마리씩 불러와 가볍게 넘겨 볼 수 있습니다.
- **기술**은 그 포켓몬이 배울 수 있는 공격기와 변화기 150개 중에서 4개를 고릅니다. 위력·명중·PP와 효과 설명이 함께 보이고, `추천`(같은 포켓몬이면 항상 같은 구성)과 `무작위` 버튼이 있습니다. 변화기는 점선 테두리로 구분됩니다.
- 종족값 합계 **제한은 없습니다**. 같은 종류의 포켓몬만 한 팀에 한 마리로 제한됩니다.

## 상대와 난이도

- 상대 3마리는 **내 팀의 종족값 합계에 맞춰** 자동으로 뽑습니다. 목표 = 내 합계 + 난이도 보정(쉬움 −120 / 보통 0 / 어려움 +90).
- 내 팀이 아주 강하면 전설·환상도 상대로 나옵니다. 상대로 뽑을 수 있는 가장 강한 후보(약 2,300)가 맞출 수 있는 최대치입니다.
- 상대의 기술은 매번 무작위(공격기 2~3 + 변화기 1~2)로 구성됩니다. 난이도에 따라 AI의 실수율도 달라집니다.

## 배틀 연출

화면 흔들림, 타격 파티클(타입 색에 금색·파랑·흰색 등을 섞음), 큰 데미지 숫자, "효과 굉장!"·"CRITICAL!"·"K.O." 배너, 체력바 잔상, 날씨 오버레이(비·햇살·모래·눈), 필드 색 번짐, 함정·벽·상태 표시, 합성 효과음(WebAudio, 파일 없음), 승리 색종이가 있습니다.

## 디자인

- **바탕은 순수한 검정**, 테마색은 **파랑**(`#2a62ff` / `#9bb8ff`)과 **금색**(`#ffb21f` / `#ffe3a6`)입니다. 금색은 주요 버튼·강조·고리, 파랑은 조명·바닥 격자·보조 강조에 씁니다.
- 포켓몬 **타입 색**은 카드 색조·타입 칩·기술 칩에 그대로 유지합니다(테마와 무관).
- **글꼴**: 강조(로고·제목·큰 글자)는 Hahmlet, 본문과 도감번호는 Pretendard.
- 토큰은 `apps/proelium/src/styles/tokens.css`, 공용 부품은 `base.css`에 있습니다.

## 저장과 외부 리소스

- 저장 키는 모두 `proelium:` 접두어입니다: `team`(내 팀과 기술), `level`(난이도), `sound`(효과음), `record`(전적). 재생 속도는 세션 저장소에만 둡니다. Holo와 같은 도메인을 쓰므로 서로의 데이터를 덮어쓰지 않습니다.
- 포켓몬 일러스트는 PokeAPI 공식 이미지를 불러오며, 실패하면 도감번호 자리표시로 바뀝니다. 글꼴은 Google Fonts(Hahmlet)와 jsDelivr(Pretendard)에서 불러옵니다.

## 알려진 과제

- **저사양 기기 성능**: 배경 오로라·바닥 격자·금색 고리·배틀 연출 등 계속 도는 효과가 많아서, 그래픽 성능이 낮은 태블릿 등에서 버벅일 수 있습니다. 효과 줄이기 모드, 배경 정적화, 작은 일러스트 사용 등 최적화를 계획하고 있습니다.
- 팀은 한 개만 저장됩니다(여러 팀 저장은 아직 없음).
- 상대 팀을 직접 구성하는 기능, 리플레이는 아직 없습니다.

# Rembrandt 1.1 (배틀 엔진)

화면과 저장소에 의존하지 않는 순수 로직 라이브러리입니다. Holo와 Proelium이 같은 엔진을 씁니다. **판단 기준: 화면 없이 Node에서 돌릴 수 있으면 Rembrandt, 아니면 앱.** `npm run check:boundaries`가 이를 검사합니다.

## 구성

| 파일 | 역할 |
|---|---|
| `packages/rembrandt/engine.js` | 배틀 엔진: 데미지·상성·상태이상·교체·변화기·날씨·필드. 사용법은 파일 상단 주석 |
| `packages/rembrandt/ai.js` | 규칙 기반 AI(쉬움/보통/어려움). 공격기와 변화기를 같은 단위로 점수화 |
| `packages/rembrandt/party.js` | 파티 규칙 검증, 상대 파티 생성, 무작위 기술 구성(`pickMoveset`) |
| `packages/rembrandt/data/battle-data.js` | 종족값·Lv100 능력치·기술·상성표 (생성 파일, 약 390KB) |
| `packages/rembrandt/data/battle-learnsets.js` | 포켓몬별로 배울 수 있는 공격기 전체 (생성 파일, 약 100KB, **Proelium만 불러옴**) |
| `packages/battle-ui/` | Holo의 전투 화면 (Proelium은 자체 화면을 씀) |

## 규칙

- 전원 Lv.100, 개체값 31, 노력치 0, 성격 보정 없음. 능력치 = HP `2B+141`, 그 외 `2B+36`. 데미지는 9세대 공식입니다.
- 3:3 턴제. 선공은 우선도 → 스피드(동률은 난수). 난수는 시드를 고정할 수 있어 결과를 재현할 수 있습니다.
- 지원: 상성(18타입), 급소, 명중/회피, 다단 히트, 풀죽음, 흡수·반동, 화상·마비·독·맹독·수면·얼음·혼란, 능력 단계(−6~+6), 교체, 발버둥.
- 아직 없음: 특성·도구, 유턴·방어교대 같은 능동 교체기, 접촉 효과가 있는 방어 기술(가시방패 등), 2턴 기술.

## 데이터

- 종족값·타입·기술·습득 기술은 PokeAPI CSV, 기술 선정 가중치는 Pokémon Showdown의 랜덤배틀 세트를 씁니다. `npm run battle:data`로 다시 만들며, 결과는 재현 가능합니다(같은 입력이면 같은 파일).
- 포켓몬 1,351종/폼, 기술 507개(공격기 357 + 변화기 150).
- 포켓몬마다 `m`(대표 공격기 4개, 자동 선정), `sm`(배울 수 있는 변화기), `ss`(그중 Showdown 세트에 나오는 것)를 가집니다.

## 변화기 (1.1에서 추가, 150개)

목록과 효과는 `tools/battle-status-moves.json`에 있습니다. 이름·명중·PP는 PokeAPI에서 가져오고, 상태이상·능력 변화·회복량은 원본과 교차 검증합니다(어긋나면 데이터 생성이 실패).

**1단계 (50개)**
- 상태이상 14: 독가루·맹독·도깨비불·전기자석파·저리가루·뱀눈초리·수면가루·버섯포자·최면술·노래하기·악마의키스·초음파·이상한빛·천사의키스
- 상대 능력 변화 12: 뽐내기·치켜세우기(혼란 겸용)·울음소리·꼬리흔들기·째려보기·싫은소리·애교부리기·모래뿌리기·연막·겁나는얼굴·실뿜기·금속음
- 자신 능력 상승 17: 칼춤·용의춤·나쁜음모·명상·벌크업·철벽·망각술·고속이동·록커트·나비춤·껍질깨기·성장·단단해지기·코튼가드·똬리틀기·배북·그림자분신
- 회복 7: HP회복·알낳기·게으름피우기·달빛·광합성·아침햇살·잠자기

**2단계 (100개) — 몇 턴 지속되는 효과**
- 날씨·필드 9: 쾌청·비바라기·모래바람·설경(눈) / 일렉트릭·그래스·미스트·사이코필드 / 트릭룸
- 함정·벽·측면 11: 스텔스록·압정뿌리기·독압정·끈적끈적네트·하얀안개 / 리플렉터·빛의장막·오로라베일 / 순풍·신비의부적·미스트
- 지속 상태 15: 씨뿌리기·도발·앙코르·사슬묶기·트집·하품·아쿠아링·뿌리박기·소원·날개쉬기·모래모으기·기합·헤롱헤롱·악몽·멸망의노래
- 보호·대타·기타 12: 방어·판별·버티기·대타출동·아픔나누기·울부짖기·날려버리기·변신·튀어오르기·흑안개·손가락흔들기·잠꼬대
- 가두기·기타 5: 검은눈빛·블록·거미집·원한·물붓기
- 능력 상승 20 / 능력 하락 14 / 상태이상 5 / 회복·정화 9 (소울비트·살을깎다·날카로운침·정화·치유의방울 등)

**규칙 요약**
- 날씨·필드·트릭룸은 5턴(순풍 4턴), 벽·신비의부적·미스트는 5턴. 날씨는 불꽃/물 위력, 모래바람 피해, 눈 속 얼음 방어, 달빛류 회복량에 영향을 줍니다.
- 필드는 땅에 있는 포켓몬에게만 적용됩니다(비행 타입 제외). 함정은 교체해 나올 때 적용되고, 나오자마자 쓰러지면 다시 교체를 고릅니다.
- 도발·앙코르·사슬묶기·트집은 사용할 수 있는 기술 자체를 제한하며, `legalActions`가 `usable:false`와 이유(`why`)를 돌려줍니다.

## 화면용 이벤트와 도우미

엔진은 한 턴을 한꺼번에 계산하고 이벤트 목록을 돌려줍니다. 화면은 이벤트를 순서대로 연출합니다.

- 이벤트: `turn switch move miss damage effective crit hits heal status stage faint text needSwitch end` + 1.1에서 추가된 `field`(날씨·필드·함정 전체 상태) `vol`(임시 상태) `types` `stages` `cure`
- `battle.ctx(side)` 데미지 계산용 날씨·필드·벽 / `battle.outspeeds(side)` / `battle.legalActions(side)`
- `makeMon(id, { moves: [...] })`는 어떤 기술 조합이든 받습니다(Proelium의 직접 선택이 이 경로).

## AI

공격기는 기대 피해(KO 가능성 포함)로, 변화기는 "그 효과가 가져다줄 체력 비율"로 같은 단위에 점수화합니다. 이미 걸린 상태이상·면역·풀 능력 단계는 쓰지 않고, 곧 쓰러질 상황에서는 준비 동작을 줄입니다. 날씨·필드는 양쪽 기술의 기대 피해 변화로, 함정은 상대의 남은 포켓몬 수로 평가합니다.

## 상대 파티 생성 (`BattleParty`)

- 종족값 합계 **상한은 없습니다**. `validate`는 3마리·종 중복만 검사합니다.
- `generateOpponent`: 목표 = 내 합계 + 난이도 보정. 한 마리당 평균 종족값 근처에서 뽑아 목표에 맞추고, 목표가 2,000을 넘으면 전설·환상도 허용하며, 맞출 수 있는 최대치를 넘으면 가장 강한 쪽으로 최대한 맞춥니다.
- `pickMoveset`: 공격기 2~3 + 변화기 1~2를 무작위로 구성합니다(역할이 겹치지 않게, Showdown 세트에 나오는 기술은 더 자주).

## 밸런스와 검증

- 테스트 103개(엔진·AI·파티·변화기 + 변화기 150개를 섞은 무작위 400판 대량 시험).
- 시뮬레이션(AI끼리): 양쪽이 변화기를 쓸 때 0번 승률 약 50%(엔진 편향 없음). 종족값 합계 100~200 차이 ≈ 승률 73%. 변화기를 섞은 구성은 공격기 4개 구성보다 승률이 약 4%p 낮고(기술별 평균 −0.8%p), 손해가 컸던 기술은 무작위 구성에서 덜 뽑히도록 가중치를 조정했습니다.
- 시뮬레이션 결과 승패는 AI 판단보다 파티 능력치·상성의 영향이 커서, 난이도의 핵심은 상대 파티 강도입니다.

# 개발자용

## 저장소 구조

```
packages/rembrandt/   배틀 엔진·AI·파티·데이터 (화면 없음, 테스트 포함)
packages/battle-ui/   Holo 전투 화면
apps/holo/            띠부씰 아카이브 (Holo 4.0)        → 배포 /
apps/proelium/        배틀 아레나 (Proelium 1.0)        → 배포 /proelium/
tools/                데이터 생성·검증·시뮬레이터·경계 검사
```

## 스크립트

| 명령 | 내용 |
|---|---|
| `npm run dev:holo` / `npm run dev:proelium` | 개발 서버 (3000 / 3001) |
| `npm run build` | 두 앱을 `dist/`와 `dist/proelium/`으로 빌드 |
| `npm run battle:data` | PokeAPI/Showdown 데이터로 `battle-data.js`·`battle-learnsets.js` 재생성 (`--sample`, `--show 6,25`, `--explain=25`) |
| `npm run battle:validate` | 데이터 무결성 검증 |
| `npm run test:battle` | 엔진·AI·파티·변화기 테스트 (103개) |
| `npm run check:boundaries` | Rembrandt가 화면·저장소에 의존하지 않는지 검사 |
| `npm run sim:battle` / `sim:ai` | 대량 시뮬레이션(대칭성·밸런스 / 난이도 매트릭스) |
| `npm run sim:status` / `sim:status-moves` | 변화기 포함 밸런스 / 변화기 150개를 하나씩 따로 측정 |

## 배포

- GitHub Pages는 Settings → Pages → Source를 **GitHub Actions**로 두면 `.github/workflows/deploy-pages.yml`이 main 병합 때마다 검사·테스트·빌드·배포를 합니다(약 1분).
- `packages/`의 일반 `<script>`/`<link>` 주소에는 파일 내용 해시(`?v=`)가 자동으로 붙습니다. 엔진을 고쳤는데 브라우저에 옛 파일이 남는 일을 막기 위함입니다.
- 같은 도메인을 공유하므로 Proelium 저장 키는 `proelium:` 접두어를 쓰고, Holo의 기존 키는 호환을 위해 그대로 둡니다.

## 기여할 때 참고

- 변화기를 추가하려면 `tools/battle-status-moves.json`에 효과를 정의하고(스키마는 `tools/build-battle-data.mjs` 상단 주석), 새 효과 키는 엔진과 `tools/validate-battle-data.mjs`의 허용 목록에 함께 추가한 뒤 `npm run battle:data`로 데이터를 다시 만듭니다.
- 밸런스를 건드렸다면 `npm run sim:status`로 대칭성(0번 승률 ≈ 50%)을 확인하세요.
