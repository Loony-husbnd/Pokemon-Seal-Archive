## 반드시 지킬 것 (시험에서 발견)

1. **복제는 깊은 복사 + 시드 교체.** `Battle.fromJSON(JSON.parse(JSON.stringify(b.toJSON())))` 후 `clone.prng = new PRNG([a, b, c, d])`. `prng.setSeed([...])` 는 쓰지 말 것(400/400 오류).
2. **상대 체력을 가리려면 디버그가 아닌 형식을 쓴다.** `gen9customgame` 은 `debug` 형식이라 정확한 체력이 나온다(`reportExactHP = !!format.debug`). 시험 9번은 `gen9anythinggoes@@@Terastal Clause` 를 썼다.
3. 화면은 `b.log`(전지적, 공개/비공개 줄이 짝으로 나옴)가 아니라 **플레이어별 스트림**(`BattleStreams.getPlayerStreams`)을 변환해야 한다. 시험 8번의 줄 중복은 이 때문이다.

## 아직 확인하지 못한 것

- 모바일 기기에서의 로딩·탐색 속도, 웹 워커로 분리했을 때의 효과.
- 현재 엔진과 같은 단위로 맞춘 속도 비교(1대1 무작위 기준: 이쪽 1.3ms/턴 대 현재 0.26ms/턴, 복제 0.46ms 대 0.17ms 로 약 3~5배).
- `State`(공식 직렬화) API 가 깊은 복사 문제를 풀어 주는지.
- 한국어 로그 문구 템플릿의 정확한 개수(606개 조합은 400판 표본이며 긴 꼬리가 있다). `@pkmn/protocol`, `@pkmn/view` 같은 파서 재사용 가능성.
- 우리 데이터의 기술 795개와 Showdown 9세대 기술 수의 차이, 메가 포켓몬 중 9세대 규칙에서 `Past` 로 분류되는 것들의 처리.
- AI 품질(일반 평가 함수 탐색)은 이번 범위가 아니다.
